## 1. 产品定位

一个 Windows 桌面小工具，解决「让电脑在某个时刻自己关机」。

核心心智是**定在几点**，不是**再等多久**。因此界面的主交互是一个可以直接拖动指针的时钟，而不是一个输入框。倒计时只是辅助手段（预设按钮）。

底层全部通过 Windows 自带的 `shutdown.exe` 实现，不自建服务、不改动系统设置、不安装驱动。

---

## 2. 范围

### 2.1 本期要做（In Scope）

1. 拖动表盘选择关机时刻（粗调，5 分钟吸附）。
2. 滚动数字轮盘选择关机时刻（可精确到 1 分钟）。
3. 表盘与轮盘双向联动。
4. 四个预设倒计时按钮：30 分钟 / 1 小时 / 2 小时 / 3 小时。
5. 下发关机计划，显示目标时刻与剩余时间，每秒刷新。
6. 查询当前计划（本软件设定的计划）。
7. 取消当前计划，带二次确认。
8. 打包为单个 exe，双击即用。

### 2.2 本期明确不做（Out of Scope）

| 不做的事 | 原因 |
|---|---|
| 定时睡眠 | `SetSuspendState` 在启用休眠的系统上会实际进入休眠而非睡眠，不可靠，见 §5.3 |
| 关机前弹窗提醒 / 系统通知 | 用户明确不做 |
| 自定义秒数输入框 | 防止输入离谱时长，误操作代价过高 |
| 多语言 | 仅简体中文 |
| 联网、账号、云同步 | 纯本地工具 |
| 计划任务式「每周重复」 | 单次计划足够，避免复杂度 |
| 查询其他软件设定的关机计划 | Windows 未提供公开查询接口，见 §5.3 |

## 3. 功能需求

### FR-01 表盘选时

- 表盘为圆形钟面，直径 320px，绘制 1~12 刻度与 60 个小刻度。
- 按住鼠标在表盘区域内拖动，指针（时针）跟随光标角度旋转，中央实时显示 `HH:MM`。
- 松开鼠标后，选中的分钟**吸附到最近的 5 分钟刻度**。
- 吸附后若分钟为 60，进位到下一小时。
- 支持键盘微调：焦点在表盘上时，`↑`/`↓` 调整分钟（±1），`←`/`→` 调整小时（±1）。

**验收**：拖动指针一周，中央数字按 5 分钟步进变化；松手后指针不会停在非 5 分钟的位置。

### FR-02 数字轮盘选时

- 两列滚轮：小时（00~23）、分钟（00~59），分钟步进 1。
- 滚动即改变选中值，中央数字同步更新。
- 当前选中项高亮居中，上下各露 1 项，边缘渐隐（尺寸依据见 `03-设计规范.md` §5.2）。

**验收**：滚到 07:23，表盘指针指向 7 点略过一点的位置。

### FR-03 双向联动

- 拖动表盘 → 轮盘自动滚到对应值。
- 滚动轮盘 → 表盘指针平滑转到对应角度。
- 联动过程不得触发对方的「用户修改」信号造成死循环。

**验收**：来回操作 20 次，两处数值始终一致，界面不卡顿、不跳动。

### FR-04 跨天判定

选定时刻与当前时刻比较：

```
候选 = 今天 HH:MM
若 候选 <= 现在 + 60 秒  → 候选 = 明天 HH:MM，并标记为「跨天」
```

- 跨天时界面必须显示「明天」字样，不允许静默处理。
- 距离现在不足 60 秒的时刻视为「已过」，按明天算。

**验收**：当前 20:00，选 19:59 → 显示「明天 19:59」；选 20:30 → 显示「今天 20:30」。

### FR-05 预设倒计时按钮

- 四个按钮：`30 分钟`、`1 小时`、`2 小时`、`3 小时`。
- 点击后直接以「当前时间 + N」为目标下发计划，无需二次确认（属于明确的一次性动作）。
- 下发成功后在状态区显示目标时刻与剩余时间。

**验收**：点「30 分钟」，状态区显示 `将于 HH:MM 关机 · 剩余 30 分 0 秒`，且系统确实进入待关机状态。

### FR-06 设定关机

- 主按钮「设定关机」，使用表盘/轮盘当前选中的时刻计算剩余秒数，调用 `shutdown /s /t <秒>`。
- 剩余秒数必须在 `60 ~ 315360000` 之间，否则拒绝并提示。
- 若已存在计划，先弹确认框：「已有计划将于 HH:MM 关机，是否覆盖？」。
- 覆盖采用两段式：先 `shutdown /a`，成功后再 `shutdown /s /t`。系统不允许直接覆盖（返回 1190）。
- 若返回 1190 但本地无记录，说明计划来自本软件之外：提示「系统中已存在一个关机计划（非本软件设定），是否取消并替换？」，用户同意后再走两段式。
- 两段式中若 `/a` 成功而 `/s /t` 失败，必须明确告知「原计划已取消、新计划未生效」，避免用户误以为已设定。
- 失败时（权限、系统拒绝）弹出明确错误码与中文说明，不得静默失败。

**验收**：人为把剩余时间设为 0 秒，程序给出提示且不下发命令。

### FR-07 查询当前计划

- 启动时读取本地记录，若目标时刻未过，显示为「已计划」。
- 运行时每秒刷新剩余时间，格式 `X 小时 Y 分 Z 秒`，不足 1 小时省略小时位。
- 目标时刻已过，自动清除记录并回到「当前无计划」。
- 界面需标注数据来源：「本软件记录」，避免误导（原因见 §5.3）。

**验收**：设定 10 分钟后的计划，关闭程序再打开，状态仍显示正确的剩余时间。

### FR-08 取消计划

- 次按钮「取消计划」，仅在存在计划时可点击。
- 点击弹二次确认：「确定取消 HH:MM 的关机计划？」。
- 调用 `shutdown /a`，返回码 0 视为成功，1116 视为「本就没有计划」。
- 无论系统返回什么，成功后都清除本地记录并刷新界面。

**验收**：设定后点取消，状态回到「当前无计划」，`shutdown /a` 再次执行返回 1116。

### FR-09 状态栏

- 常驻显示三种状态之一：
  - `当前无计划`（灰）
  - `将于 明天 07:30 关机 · 剩余 11 小时 28 分 3 秒`（主题色）
  - `已取消` / 错误提示（红，3 秒后回到默认）
- 刷新频率 1 秒，与系统时钟对齐。
- 文案中的动作词随当前模式变化（关机 / 重启 / 锁定 / 休眠）。

### FR-10 托盘常驻与关窗询问

- 关闭主窗口时弹出选择：`最小化到托盘` / `退出程序`。
- 对话框带「不再显示」选项；勾选后记住该次选择，之后按上次的选择直接执行。
- 记住的选择可在设置中改为「每次询问 / 总是托盘 / 总是退出」。
- 最小化到托盘后：双击托盘图标恢复主窗口；主界面点「最小化」同样进托盘。
- 验收：连续关闭窗口 3 次，第 1 次弹选择、后 2 次不再弹且行为与上次一致；设置改回「每次询问」后恢复弹窗。

### FR-11 开机自启（默认关）

- 设置中提供开关，默认关闭。
- 开启时写入 `HKCU\Software\Microsoft\Windows\CurrentVersion\Run`，键名 `ShutdownScheduler`，值为 exe 完整路径；关闭时删除该键。
- 不写服务、不建计划任务、不改组策略。
- 验收：开启后重启系统，托盘图标出现；关闭后重启，托盘不出现；注册表中无残留键。

### FR-12 托盘显示剩余时间（默认开）

- 悬停托盘图标时，tooltip 显示当前状态：`当前无计划` 或 `将于 23:30 关机 · 剩余 1 小时 20 分`。
- 默认开启，可关闭；关闭后 tooltip 只显示应用名。
- 验收：悬停可见倒计时；关掉后 tooltip 仅应用名。

### FR-13 动作类型

- 可选四种：`关机` / `重启` / `锁定` / `休眠`，在设置中切换。
- 执行方式：
  - 关机、重启走 `shutdown /s`、`shutdown /r`，加 `/t <秒>`，**系统级**，进程退出不影响。
  - 锁定走 `rundll32 user32.dll,LockWorkStation`，休眠走 `shutdown /h`，**由常驻程序到点执行**，进程退出即失效。
- 切换动作类型时，若当前有计划，先弹确认「切换动作类型将取消当前计划」，确认后取消并切换。
- 依赖常驻的计划（锁定/休眠）在用户退出时强警告：`该计划依赖程序常驻，退出后将失效`。
- 主按钮与状态条文案随动作变化：`设定关机` / `设定重启` / `设定锁定` / `设定休眠`。
- 验收：四种动作均能设定并取消；关机/重启设定后直接杀进程仍按时执行；锁定/休眠杀进程后失效，且退出前有警告。

### FR-14 主题色随模式变化

- 主题色表：

| 模式 | 主题色 |
|---|---|
| 关机 | `#F25C34` 橙 |
| 重启 | `#2F80ED` 蓝 |
| 锁定 | `#7C5CFC` 紫 |
| 休眠 | `#00A3A3` 青 |

- 影响范围：主按钮（填充）、状态点点、表盘中心点、模式提示行色块。
- 窗口最上方新增一行：`当前模式：关机` + 对应色块，高度约 20px。
- 验收：依次切换四种模式，上述四处颜色同步变化，无残留旧色。

## 5. 边界与异常

### 5.1 输入边界

| 场景 | 处理 |
|---|---|
| 选中的时刻距现在 < 60 秒 | 视为已过，顺延到明天 |
| 剩余秒数 > 315360000（约 10 年） | 不可能出现（最大 24 小时），仍做断言防御 |
| 用户拖动后立刻点设定 | 以松手后的吸附值为准，不读取拖动中途值 |
| 系统时间被手动修改 | 每秒重新取 `datetime.now()` 计算剩余，不做累加 |

### 5.2 shutdown 返回码

| 返回码 | 含义 | 处理 |
|---|---|---|
| 0 | 成功 | 正常 |
| 1116 | 没有正在进行的关机 | 提示「当前没有可取消的计划」 |
| 1190 | 已存在关机计划 | 系统**不接受直接覆盖**，必须先 `/a` 再 `/s /t`（见 §5.3） |
| 5 | 拒绝访问 | 提示需要权限，建议右键以管理员身份运行 |
| 其他 | 未知 | 原样显示返回码与命令输出 |

> 说明：`shutdown.exe` 的输出为系统 OEM 编码（中文系统为 GBK），读取时须按 `locale.getpreferredencoding()` 解码，不能用 UTF-8。

### 5.3 查询接口缺失（重要限制）

Windows **没有**公开 API 用于查询「当前是否存在待定关机、目标时刻是几点」。

已知的 `shutdown /a` 会取消计划，属于破坏性操作，不能用来查询。

因此 v1.0 采用：

- 计划以本地 JSON 记录为准（`%LOCALAPPDATA%\ShutdownScheduler\state.json`）。
- 界面明确标注数据来自「本软件记录」。
- **已知局限**：若计划是别的程序设定的，或在别处被取消，本软件无法感知。准确性矩阵如下：

| 实际情况 | 软件显示 | 是否准确 |
|---|---|---|
| 本软件设定、未被动过 | 已计划 + 正确剩余时间 | 准确 |
| 本软件设定、被别处取消 | 仍显示「已计划」 | **假阳性** |
| 其他来源设定（cmd / 第三方） | 显示「当前无计划」 | **假阴性** |
| 本软件取消、别处又设定 | 显示「无计划」 | **假阴性** |
| 确实无计划 | 显示「无计划」 | 准确 |

> 说明：假阴性有机会被纠正——用户点「设定关机」时会撞上 1190，从而得知「系统中已存在计划」。假阳性没有任何自动纠正手段，只能等目标时刻过去后记录自然失效。

### 5.5 常驻依赖（v1.1 新增限制）

Windows 没有为「锁定」「休眠」提供系统级定时能力，只能由本程序驻留并在到点后调用命令。由此产生：

- 进程被任务管理器结束、或系统重启，计划**静默失效**，没有任何系统级残留。
- 关机 / 重启不受此限制，仍走 `shutdown` 计时器。
- 缓解措施：依赖常驻的计划，退出时强警告；托盘常驻本身就是为了降低误退出的概率。
- 该限制需写入 README 与设置界面的说明文字。

后续版本可考虑「试探 + 重设」方案（`/a` 后按剩余秒数立即重新 arm），但因存在计划丢失风险，本期不实现。

**例外：1190 是一个安全的被动探测信号。** 实测确认，当系统中已存在待定关机时，再执行 `shutdown /s /t` 会返回 1190 而不是覆盖。因此「用户主动点设定」这一动作本身可以告诉我们「别处有计划」——虽然不知道它几点执行。界面据此提示：「系统中已存在一个关机计划（非本软件设定），是否取消并替换？」。该信号只在主动设定时出现，不能用于后台轮询。

### 5.4 其他异常

- 本地记录文件损坏 → 视为无计划，静默重建，日志记录。
- 系统关机过程中程序被强制结束 → 不做特殊处理，系统会正常关机。
- 用户双击图标重复启动 → 检测单实例，第二次启动时把已有窗口置前。

## 6. 术语

| 术语 | 含义 |
|---|---|
| 计划（Plan） | 已下发到 Windows 的待定关机，由系统内核计时 |
| 目标时刻 | 计划实际执行关机的绝对时间点 |
| 吸附 | 拖拽结束后把分钟值对齐到 5 分钟刻度 |
| 跨天 | 选中的时刻早于当前时刻，实际执行落在次日 |
